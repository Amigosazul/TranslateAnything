# 02 · 技术方案

## 技术栈

- **Tauri 2 + Rust**（stable-msvc 工具链），前端用 **Vite + 原生 TS**（界面极简，不引 React/Vue 这类框架；若设置页变复杂再说）。
- 包管理：pnpm。

## 窗口方案

1. **框选遮罩 overlay**：覆盖光标所在显示器，背景 1/255 透明度（不置灰，但能接收鼠标），只画选区边框；框选完成后销毁，把选区（物理像素）交给后端。
2. **翻译框 frame-N**（`live.rs`）：无边框、透明、置顶、不抢焦点，并且：
   - 实时截屏不截屏幕，而是截翻译框**下面的窗口**（`capture::capture_under`）：按 Z 序找出与框相交的其他程序窗口（跳过本进程、隐藏/cloaked、鼠标穿透的悬浮层），直到遇到完全盖住框的那个，再从下往上逐个 `PrintWindow(PW_RENDERFULLCONTENT)` 拼成框内画面。这样截到的始终是原始内容，不会把译文截进去，也不用隐藏窗口，不会闪烁；全屏 1920×1080 窗口约 26ms。
   - 弃用方案：`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 会让透明的 WebView2 窗口在屏幕上也不可见（2026-11-16 真机确认），不要再用。
   - 已知限制：不支持 `PrintWindow` 的程序（少数游戏、硬件加速视频）截到的可能是黑屏；只盖住一部分的半透明分层窗口会被忽略。
   - 默认 `set_ignore_cursor_events(true)` 鼠标穿透。悬停循环每 40ms 读一次光标位置，光标落在边缘（6 CSS px）或右上角工具条上时临时关闭穿透，以便 `startResizeDragging` / `startDragging` / 点击按钮；拖拽过程中保持可交互。
3. **设置窗 settings**（M3）：普通窗口，从托盘菜单打开。

## 数据流（实时循环，每个翻译框一个）

```
每 150ms：截取框内画面（PrintWindow 截下层窗口，不含翻译框自身）
  └─ 与上一帧比较，变化像素 < 0.2% 且框未移动 → 跳过
  └─ 估算整体滚动位移（行/列签名匹配）→ emit("shift") 前端先平移现有译文
  └─ OCR（含每个单词坐标）→ layout.rs 归并段落块（按大间距拆栏、按行高/行距/水平重叠合段）
       → 取样背景色（外框中位数）与文字色（与背景差异最大的像素）
  └─ 段落原文查缓存：命中直接用；未命中的批量请求翻译（同一时刻只有一个请求在途，失败 3s 后重试）
  └─ emit("layout") → 前端按原位置画色块 + 译文，字号从原行高开始逐步缩小到不溢出
译文到达 → 标记 dirty → 下一轮重新推送版面
```

- 缓存键是段落原文，所以滚动、缩放后同一段文字不会重复翻译，只有新进入框内的文字才会产生请求。
- 贴着上下边缘、被截断的行不参与翻译（识别不可靠），滚动进来完整后再翻。
- 目标语言为中文时跳过本身就是中日文的段落，纯数字/符号段落也不翻译。
- 实测（1000×700 区域）：OCR + 分段约 50ms，Edge 批量翻译约 0.5s。

坑位提醒：
- **DPI**：后端一律用物理像素；前端除以 `devicePixelRatio` 换成 CSS 像素。
- **OCR 坐标**：OCR 前图像可能被放大/缩小，单词坐标要除回缩放倍数。
- **OCR 语言**：`OcrEngine::TryCreateFromUserProfileLanguages` 优先；允许配置指定语言。

## 翻译 Provider 抽象

```rust
#[async_trait]
pub trait Translator: Send + Sync {
    async fn translate(&self, text: &str, target_lang: &str) -> Result<String, TranslateError>;
}
```

**默认不走大模型。** 引擎清单在 `translate::CATALOG`（id、中文名、是否需要 key、是否官方、需要的字段），前端可通过 `engine_catalog` 命令读取，供 M3 设置界面渲染。

| 引擎 id | 实现 | key | 国内直连 | 参考 |
|---|---|---|---|---|
| `edge`（默认） | `POST edge.microsoft.com/translate/translatetext?from=&to=..`，体 `["原文"]`，无鉴权；失败自动回退 `bing` | 免 | 能 | kiss-translator |
| `bing` | `GET cn.bing.com/translator` 抓 `IG`、`data-iid`、`params_AbusePreventionHelper=[key,token,ttl]` → `POST /ttranslatev3?isVertical=1&IG=&IID=` 表单；token 过半有效期刷新，响应 `statusCode==205` 重取 | 免 | 能 | Easydict、translate-shell |
| `google_free` | `GET translate.googleapis.com/translate_a/single?client=gtx&dt=t&dj=1&sl=auto&tl=..&q=..`，拼接 `sentences[].trans`；429/验证页给出提示；`base_url` 可换镜像 | 免 | 需代理 | pot-desktop、STranslate |
| `microsoft` | Azure Translator v3 官方 API，需 `api_key`、`region` | 需 | 能 | — |
| `deepl` | DeepL API v2，`:fx` 结尾 key 走免费端点 | 需 | 能 | pot-desktop |
| `deeplx` | 用户自建 DeepLX，`POST base_url {text,source_lang,target_lang}`，译文在 `data` | 可选令牌 | 视部署 | pot-desktop |
| `google` | Cloud Translation Basic v2 官方 API | 需 | 需代理 | — |
| `openai` | OpenAI 兼容 `/chat/completions`，需 `base_url`、`model` | 需 | 视服务商 | — |

- 2026-11-16 实测：`edge`、`bing` 直连可用，`google_free` 经 Clash 可用；Edge 的 `translate/auth` 已 404（pot-desktop 仍在用，已失效）。
- 免 key 接口都是非官方用法，近一年各开源项目均遇到过失效（Edge auth 404、DeepL jsonrpc 503、Google gtx 429），所以设计为**主引擎 + 回退链**，并保留官方 API。
- **不采用**：网上流传的 Google API key、逆向得到的微软签名私钥、伪装 DeepL iOS 客户端的接口。
- 传统引擎会逐行翻译，发送前用 `merge_lines` 把 OCR 硬换行合并成自然段；大模型直接收原文，由提示词处理。
- 每个引擎可单独配 `proxy`：留空 = 直连；`system` = 跟随系统环境变量；其他 = 代理地址（如 Clash `http://127.0.0.1:7897`）。
- 浮窗报错时逐个列出各引擎的失败原因，并附上识别出的原文。
- 配置决定一切，不在代码里写死任何服务商的 key。

**扩展点（P2 视觉直译）**：trait 增加 `translate_image(&self, png: &[u8], target_lang)` 默认返回"不支持"；OpenAI 兼容实现用 VLM 传 base64 图片，跳过 OCR。模式由配置 `mode: "ocr" | "vision"` 切换。

## 配置文件

`~/.translate-filter/config.json`（仓库放 `config.example.json`）：

```json
{
  "hotkey": "Alt+T",
  "target_lang": "zh-CN",
  "mode": "ocr",
  "ocr_lang": "auto",
  "engine": "edge",
  "fallback": ["bing", "google_free"],
  "engines": {
    "edge": {},
    "bing": {},
    "google_free": {
      "proxy": "http://127.0.0.1:7897"
    },
    "microsoft": {
      "api_key": "在此填写你的 key",
      "region": "eastasia"
    },
    "deepl": {
      "api_key": "在此填写你的 key"
    },
    "deeplx": {
      "base_url": "http://127.0.0.1:1188/translate"
    },
    "openai": {
      "base_url": "https://api.example.com/v1",
      "api_key": "在此填写你的 key",
      "model": "gpt-4o-mini"
    }
  }
}
```

- `engine`：主用引擎 id；`fallback`：失败后依次尝试的引擎；`engines`：各引擎参数，键为引擎 id。
- 同一类型要配多份时（例如两个大模型服务），在条目里写 `"type": "openai"`，键名随意。
- 配置文件不存在时使用默认值（`edge`，免 key 开箱即用）；旧版 `provider` 单引擎写法仍兼容。

## 里程碑建议

1. **M1 跑通链路** ✅：快捷键 → 框选 → 截屏 → OCR → 翻译 → 显示。
2. **M2 沉浸式实时翻译**：原位覆盖、实时刷新、跟随滚动缩放、只翻新内容、鼠标穿透、工具条。
3. **M3 可配置**：配置文件 + 设置界面 + 托盘。
4. **M4 打磨**：多显示器、多浮窗、开机自启、视觉直译扩展。
