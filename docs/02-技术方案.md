# 02 · 技术方案

## 技术栈

- **Tauri 2 + Rust**（stable-msvc 工具链），前端用 **Vite + 原生 TS**（界面极简，不引 React/Vue 这类框架；若设置页变复杂再说）。
- 包管理：pnpm。

## 窗口方案

1. **框选遮罩 overlay**：覆盖光标所在显示器，背景 1/255 透明度（不置灰，但能接收鼠标），只画选区边框；框选完成后销毁，把选区（物理像素）交给后端。
2. **翻译框 frame-N**（`live.rs`）：无边框、透明、置顶、不抢焦点，并且：
   - 实时截屏不截屏幕，而是截翻译框**下面的窗口**（`capture::capture_under`）：按 Z 序找出与框相交的其他程序窗口（跳过本进程、隐藏/cloaked、鼠标穿透的悬浮层），直到遇到完全盖住框的那个，再从下往上逐个 `PrintWindow(PW_RENDERFULLCONTENT)` 拼成框内画面。这样截到的始终是原始内容，不会把译文截进去，也不用隐藏窗口，不会闪烁；全屏 1920×1080 窗口约 26ms。
   - 弃用方案：`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 会让透明的 WebView2 窗口在屏幕上也不可见（2026-11-16 真机确认），不要再用。
   - 已知限制：不支持 `PrintWindow` 的程序（少数游戏、硬件加速视频）截到的可能是黑屏；只盖住一部分的半透明分层窗口会被忽略。
   - 默认 `set_ignore_cursor_events(true)` 鼠标穿透。悬停循环每 40ms 读一次光标位置，光标落在边缘（6 CSS px）或右上角工具条上时临时关闭穿透，以便 `startResizeDragging` / `startDragging` / 点击按钮；拖拽过程中保持可交互。
3. **设置窗 settings**（M3）：普通窗口，从托盘菜单打开。

## 数据流（实时循环，每个翻译框一个）

```
每 150ms：截取框内画面（PrintWindow 截下层窗口，不含翻译框自身）
  └─ 与上一帧比较，变化像素 < 0.2% 且框未移动 → 跳过
  └─ 估算整体滚动位移（行/列签名匹配）→ emit("shift") 前端先平移现有译文
  └─ OCR（含每个单词坐标）→ layout.rs 归并段落块（按大间距拆栏、按行高/行距/水平重叠合段）
       → 取样背景色（外框中位数）与文字色（与背景差异最大的像素）
  └─ 段落原文查缓存：命中直接用；未命中的批量请求翻译（同一时刻只有一个请求在途，失败 3s 后重试）
  └─ emit("layout") → 前端按原位置画色块 + 译文，字号从原行高开始逐步缩小到不溢出
译文到达 → 标记 dirty → 下一轮重新推送版面
```

- 缓存键是段落原文，所以滚动、缩放后同一段文字不会重复翻译，只有新进入框内的文字才会产生请求。
- 贴着上下边缘、被截断的行不参与翻译（识别不可靠），滚动进来完整后再翻。
- 目标语言为中文时跳过本身就是中日文的段落，纯数字/符号段落也不翻译。
- 实测（1000×700 区域）：OCR + 分段约 50ms，Edge 批量翻译约 0.5s。

坑位提醒：
- **DPI**：后端一律用物理像素；前端除以 `devicePixelRatio` 换成 CSS 像素。
- **OCR 坐标**：OCR 前图像可能被放大/缩小，单词坐标要除回缩放倍数。
- **OCR 语言**：`OcrEngine::TryCreateFromUserProfileLanguages` 优先；允许配置指定语言。

## 两种显示模式

| | 悬浮窗模式（`live.rs`） | 沉浸模式（`immersive/`） |
|---|---|---|
| 触发 | 快捷键框选区域 | 配置好目标应用后自动接管，`Alt+Shift+T` 切换译文/原文 |
| 取文字 | 截屏 + OCR | 直接读界面文字（DOM），不识别图像 |
| 显示 | 透明置顶窗口盖在原文上 | 应用自己用译文排版渲染，没有任何浮层 |
| 适用 | 任何程序（游戏、图片、视频字幕、自绘界面） | 已接入通道的程序（目前：Electron / Chromium 内核） |

两种模式共用翻译引擎链（`translate_batch_with_fallback`）和译文本地库，可以同时开启：沉浸模式接管得了的应用就原地改写，接管不了的照样框选用悬浮窗。

## 译文本地库（`store.rs`）

- 位置 `~/.translate-filter/translations.db`，SQLite（WAL）。表 `translations`，主键（目标语言，原文），另存译文、引擎、命中次数、首次/最近使用时间，以及为设置界面"改译/词典"预留的 `manual` 标记（自动翻译不覆盖手工译文）。
- `translate_batch_with_fallback` 先批量查库，只把未命中的原文交给引擎，结果写回库；全部命中时返回的引擎名为"本地缓存"，不发任何网络请求。`persist_cache: false` 可关闭。
- 不区分引擎：换引擎后旧译文继续有效；想全部重翻就删掉这个文件。
- 译文与原文相同（产品名、专有名词）也入库，免得每次都去问引擎；空译文不入库。单条原文超过 4000 字不入库。
- 悬浮窗模式内存里的段落缓存仍保留，作为库前面的一层。

## 术语表（`translate::glossary`）

- 传统翻译引擎翻单个界面词没有上下文，实测 reclaude 客户端里 "New → 新款"、"Artifacts → 文物"、"Auto → 汽车"、"On-call → 随叫随到"。术语表按**整条原文精确匹配**（忽略首尾空白），命中的既不查库也不请求引擎，优先级：自定义 `glossary` > 内置术语表 > 译文库 > 引擎。
- 内置术语表 `translate/glossary.json` 按目标语言分组，收录常见界面词和 reclaude 客户端用到的词；`builtin_glossary: false` 可关闭。
- 自定义 `glossary` 写在配置里；译文写成与原文相同即"保持原样不翻"。后续设置界面的"改译"功能写到译文库的 `manual` 条目或这里。
- 沉浸模式注入页面时把术语表并入预加载，命中当场替换。
- 句子里夹带的产品名（"Fable 5.2 is here…" → "《Fable 5.2》……"）术语表管不到，后续可考虑"术语保护"：翻译前把专有名词换成占位符、翻译后还原。

## 沉浸模式（`immersive/`）

思路参考 Android 上的 LSPosed 文字替换模块：在目标应用**自己的进程里**拦截文字，替换成译文后再交给应用渲染，软件本体（exe、资源包）一个字节都不改。Windows 上界面框架很杂，按"通道"逐个接入，接管不了的回退悬浮窗模式。

### 通道一：Electron / Chromium 内核（已实现，首个适配 reclaude 客户端）

1. 目标应用带 `--remote-debugging-port=<端口>` 启动（只监听 127.0.0.1）。reclaude 启动客户端时会带自己的代理、用户数据目录等参数，没法直接追加，所以用 `scripts/immersive-launch.ps1`：读取正在运行的客户端主进程完整命令行并保存，等用户从托盘完全退出后，用同样的命令行加上调试端口重新打开。
2. translate-filter 启动后为每个配置的目标开守护任务，每 2 秒轮询 `http://127.0.0.1:<端口>/json/list`（必须直连，环境变量里的代理会把本机请求也转走），对每个新出现的页面目标（page / iframe / webview）建一条 CDP 连接：
   - `Runtime.addBinding`（`executionContextName` = 隔离环境名）：页面脚本通过 `__tfSend()` 把原文发回主程序；
   - `Page.addScriptToEvaluateOnNewDocument`（`worldName` = 隔离环境名）：以后每次刷新/跳转自动注入；
   - 对已加载的文档，逐个框架 `Page.createIsolatedWorld` + `Runtime.evaluate` 注入一次。
3. `inject.js` 运行在**隔离环境**（isolated world）：与页面脚本互不可见、只共享 DOM，不污染页面全局变量，也不受页面 CSP 限制。它遍历文本节点和 `placeholder` / `title` 属性，`MutationObserver` 持续跟踪新增节点、文字和属性变化：
   - 先查页面内缓存（注入时预加载本地库最近常用的 5000 条），命中就在观察回调里当场替换，渲染前完成，不闪原文；
   - 未命中的攒 30ms 一批（每批最多 200 条）发给主程序，主程序查库/翻译后用 `__tf.receive()` 回填；失败时 `__tf.failed()`，10 秒后重试；
   - 记录每个节点的原文和"我们写进去的译文"：节点内容等于我们写入的值时忽略（避免自触发），被页面改成别的值就当新原文重翻；
   - 首尾空白原样保留，只翻中间部分；
   - 不碰的区域：`script/style/code/pre/kbd/samp/textarea/input/select/svg/canvas`、可编辑区（`contenteditable`，用户正在输入的内容绝不能改）、`translate="no"` / `.notranslate`，以及配置里的 `skip_selectors`；`select` 整个跳过，因为没有 `value` 属性的 `option` 改文字会连带改掉提交值；
   - 过滤规则与悬浮窗一致（字母少于 2 个、目标为中文时本身以中日文为主的不翻），另外单个"词"像路径、文件名、版本号、变量名的不翻，带数字的 3 词以内短文本（"Opus 5.5"、"Node 22"，多为产品/型号名）也不翻；
   - `__tf.setEnabled(false)` 把所有改过的文字恢复原文并停止监听，`true` 时重新全量扫描。
4. 已知限制与风险：
   - 改的是界面上的 DOM，复制界面文字会复制到译文；
   - 以文本节点为单位翻译，一句话被 `<b>` / `<a>` 拆成几段时译文会被切碎（界面按钮、菜单基本不受影响，长段正文可能受影响，必要时用 `skip_selectors` 排除）；
   - Canvas 渲染的内容（在线文档画布等）没有 DOM 文本，接管不了；
   - 调试端口开着时，本机任何程序都能通过它操控该应用（包括已登录的账号），用完建议照常重启应用关掉端口。

## 翻译 Provider 抽象

```rust
#[async_trait]
pub trait Translator: Send + Sync {
    async fn translate(&self, text: &str, target_lang: &str) -> Result<String, TranslateError>;
}
```

**默认不走大模型。** 引擎清单在 `translate::CATALOG`（id、中文名、是否需要 key、是否官方、需要的字段），前端可通过 `engine_catalog` 命令读取，供 M3 设置界面渲染。

| 引擎 id | 实现 | key | 国内直连 | 参考 |
|---|---|---|---|---|
| `edge`（默认） | `POST edge.microsoft.com/translate/translatetext?from=&to=..`，体 `["原文"]`，无鉴权；失败自动回退 `bing` | 免 | 能 | kiss-translator |
| `bing` | `GET cn.bing.com/translator` 抓 `IG`、`data-iid`、`params_AbusePreventionHelper=[key,token,ttl]` → `POST /ttranslatev3?isVertical=1&IG=&IID=` 表单；token 过半有效期刷新，响应 `statusCode==205` 重取 | 免 | 能 | Easydict、translate-shell |
| `google_free` | `GET translate.googleapis.com/translate_a/single?client=gtx&dt=t&dj=1&sl=auto&tl=..&q=..`，拼接 `sentences[].trans`；429/验证页给出提示；`base_url` 可换镜像 | 免 | 需代理 | pot-desktop、STranslate |
| `microsoft` | Azure Translator v3 官方 API，需 `api_key`、`region` | 需 | 能 | — |
| `deepl` | DeepL API v2，`:fx` 结尾 key 走免费端点 | 需 | 能 | pot-desktop |
| `deeplx` | 用户自建 DeepLX，`POST base_url {text,source_lang,target_lang}`，译文在 `data` | 可选令牌 | 视部署 | pot-desktop |
| `google` | Cloud Translation Basic v2 官方 API | 需 | 需代理 | — |
| `openai` | OpenAI 兼容 `/chat/completions`，需 `base_url`、`model` | 需 | 视服务商 | — |

- 2026-11-16 实测：`edge`、`bing` 直连可用，`google_free` 经 Clash 可用；Edge 的 `translate/auth` 已 404（pot-desktop 仍在用，已失效）。
- 免 key 接口都是非官方用法，近一年各开源项目均遇到过失效（Edge auth 404、DeepL jsonrpc 503、Google gtx 429），所以设计为**主引擎 + 回退链**，并保留官方 API。
- **不采用**：网上流传的 Google API key、逆向得到的微软签名私钥、伪装 DeepL iOS 客户端的接口。
- 传统引擎会逐行翻译，发送前用 `merge_lines` 把 OCR 硬换行合并成自然段；大模型直接收原文，由提示词处理。
- 每个引擎可单独配 `proxy`：留空 = 直连；`system` = 跟随系统环境变量；其他 = 代理地址（如 Clash `http://127.0.0.1:7897`）。
- 浮窗报错时逐个列出各引擎的失败原因，并附上识别出的原文。
- 配置决定一切，不在代码里写死任何服务商的 key。

**扩展点（P2 视觉直译）**：trait 增加 `translate_image(&self, png: &[u8], target_lang)` 默认返回"不支持"；OpenAI 兼容实现用 VLM 传 base64 图片，跳过 OCR。模式由配置 `mode: "ocr" | "vision"` 切换。

## 配置文件

`~/.translate-filter/config.json`（仓库放 `config.example.json`）：

```json
{
  "hotkey": "Alt+T",
  "target_lang": "zh-CN",
  "mode": "ocr",
  "ocr_lang": "auto",
  "engine": "edge",
  "fallback": ["bing", "google_free"],
  "persist_cache": true,
  "builtin_glossary": true,
  "glossary": {
    "Opus": "Opus",
    "Artifacts": "工件"
  },
  "immersive": {
    "enabled": true,
    "hotkey": "Alt+Shift+T",
    "targets": [
      { "name": "reclaude 客户端", "port": 39222, "url_prefixes": [], "skip_selectors": [] }
    ]
  },
  "engines": {
    "edge": {},
    "bing": {},
    "google_free": {
      "proxy": "http://127.0.0.1:7897"
    },
    "microsoft": {
      "api_key": "在此填写你的 key",
      "region": "eastasia"
    },
    "deepl": {
      "api_key": "在此填写你的 key"
    },
    "deeplx": {
      "base_url": "http://127.0.0.1:1188/translate"
    },
    "openai": {
      "base_url": "https://api.example.com/v1",
      "api_key": "在此填写你的 key",
      "model": "gpt-4o-mini"
    }
  }
}
```

- `engine`：主用引擎 id；`fallback`：失败后依次尝试的引擎；`engines`：各引擎参数，键为引擎 id。
- 同一类型要配多份时（例如两个大模型服务），在条目里写 `"type": "openai"`，键名随意。
- 配置文件不存在时使用默认值（`edge`，免 key 开箱即用）；旧版 `provider` 单引擎写法仍兼容。
- `persist_cache`：是否使用译文本地库（默认开）。
- `builtin_glossary` / `glossary`：内置术语表开关、自定义术语表（见"术语表"一节）。
- `immersive`：沉浸模式。`enabled` 总开关；`hotkey` 译文/原文切换快捷键（默认 `Alt+Shift+T`）；`targets` 要接管的应用，每项 `name`、`port`（调试端口）、`url_prefixes`（只处理这些地址开头的页面，留空 = 全部）、`skip_selectors`（额外不翻译的元素）。默认带一项 reclaude 客户端（端口 39222）。

## 里程碑建议

1. **M1 跑通链路** ✅：快捷键 → 框选 → 截屏 → OCR → 翻译 → 显示。
2. **M2 沉浸式实时翻译**：原位覆盖、实时刷新、跟随滚动缩放、只翻新内容、鼠标穿透、工具条。
3. **沉浸模式**（与 M2 并行）：译文本地库 ✅、术语表 ✅、Electron/Chromium 通道 ✅（首个适配 reclaude 客户端）；之后按需接 XAML / Win32 / Qt 通道。
4. **M3 可配置**：配置文件 + 设置界面 + 托盘（含沉浸模式目标管理、一键以沉浸模式重启应用、译文库查看与改译）。
5. **M4 打磨**：多显示器、多浮窗、开机自启、视觉直译扩展。
